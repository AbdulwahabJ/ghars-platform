3. AUTOMATED REGRESSION TESTS

Create a small maintainable automated Phase 1 regression suite.

Use suitable stable tooling such as:

- Vitest,
- Supertest for API tests,
- and Playwright for essential UI smoke tests.

At minimum, automate tests for:

A. First-run setup:
- invalid setup key is rejected,
- weak password is rejected,
- first Admin can be created,
- setup is permanently rejected after a user exists.

B. Authentication:
- login succeeds with valid credentials,
- invalid login returns a generic failure,
- protected endpoints reject anonymous access,
- logout invalidates the session.

C. CSRF / same-origin protection:
- legitimate same-origin mutation succeeds,
- cross-origin mutation is rejected.

D. Patients:
- patient creation succeeds,
- duplicate active file number is rejected,
- duplicate archived file number is rejected with the correct conflict type,
- archived patient can be restored,
- file number remains globally unique.

E. Concurrency:
- two simultaneous requests attempting to create the same file number result in only one patient record.

F. Mobile normalization:
- 05XXXXXXXX becomes 9665XXXXXXXX,
- +9665XXXXXXXX is accepted,
- Arabic digits are normalized,
- a foreign local number without a country code is rejected,
- the original display value remains preserved.

G. Onboarding:
- welcome appears for a new user,
- completion or skipping is saved per user,
- it does not appear again automatically,
- the guided tour can still be manually restarted.

Tests must be repeatable and must not depend on the current real development records.

Use isolated test data and clean it safely.
