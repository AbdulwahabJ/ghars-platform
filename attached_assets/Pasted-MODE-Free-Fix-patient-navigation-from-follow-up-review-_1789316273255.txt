MODE: Free

Fix patient navigation from follow-up/review notifications and dashboard follow-up surfaces.

CURRENT PROBLEM:

When the user clicks:

- فتح الملف from an overdue follow-up
- a follow-up notification
- a review/follow-up item
- a notification related to a patient follow-up

Ghars currently opens the patient's default tab:

بيانات المريض
Patient Data

This is contextually wrong.

==================================================
1. REQUIRED DESTINATION
==================================================

For ANY navigation originating from a follow-up/review context, open:

Patient File
→ إجراءات المريض
→ المتابعات وسجل التواصل

Arabic:

إجراءات المريض
ثم:
المتابعات وسجل التواصل

English:

Patient Procedures
then:
Follow-ups & Communication Log

Do NOT open the Patient Data tab for these actions.

==================================================
2. CREATE A CANONICAL DEEP-LINK
==================================================

Do not implement separate hacks in every component.

Create/reuse one canonical patient deep-link mechanism.

Conceptually use something like:

/patients/{patientId}?tab=procedures&section=followups

And when a specific follow-up exists:

/patients/{patientId}?tab=procedures&section=followups&followupId={followupId}

The exact route/query format may follow the current routing architecture.

Do NOT introduce a second Patient File route.

3. PATIENT FILE BEHAVIOR
==================================================

When Patient File loads with:

tab=procedures

When:

section=followups

after the procedures content is rendered:

scroll smoothly to:

المتابعات وسجل التواصل

Account for the sticky Ghars header so the section title is not hidden underneath it.

==================================================
4. SPECIFIC FOLLOW-UP TARGET
==================================================

If followupId is present:

1. Open إجراءات المريض
2. Scroll to المتابعات وسجل التواصل
3. Find the corresponding follow-up record
4. Scroll it into visible position
5. Apply a subtle temporary highlight for approximately 1.5–2.5 seconds

Use a restrained Ghars-style highlight.

Do NOT:
- flash aggressively
- use animation loops
- change the follow-up status

If the follow-up no longer exists:
fall back gracefully to the Follow-ups section.
