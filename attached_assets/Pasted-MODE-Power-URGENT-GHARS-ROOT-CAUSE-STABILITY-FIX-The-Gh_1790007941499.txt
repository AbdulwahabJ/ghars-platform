1. Navigation between pages sometimes hangs.

3. Clicking appears to do nothing.
4. Sometimes refresh is also slow.
5. The issue is intermittent, not limited to one page.

This is now a RELEASE-BLOCKING stability issue.

STOP all feature development.

DO NOT add new features.
DO NOT redesign anything.
DO NOT publish.
DO NOT mask the issue with more spinners.
DO NOT blindly rollback.

Find and fix the actual root cause.

2. WHEN CLICKS STOP WORKING — INSPECT THE DOM
==================================================

THIS IS CRITICAL.

When the UI becomes non-clickable, DO NOT refresh immediately.

Inspect the page in the broken state.

At the exact coordinates of a button that does not respond, inspect:

document.elementFromPoint(x, y)

Determine which element is actually receiving the pointer.

Check for invisible/full-screen elements such as:

- fixed overlays
- modal backdrops
- Sheet overlays
- Dialog overlays
- Popover layers
- loading screens
- attachment viewer backdrops
- stale dropdown layers
- full-screen divs with opacity 0
- z-index layers
- pointer-events interception

Return the exact blocking DOM element if found.

==================================================
3. CHECK BODY POINTER EVENTS
==================================================

When the bug occurs inspect:

document.body.style.pointerEvents
getComputedStyle(document.body).pointerEvents

Also inspect:

document.documentElement
#root

Look specifically for:

pointer-events: none

being left behind after:

- Dialog
- AlertDialog
- DropdownMenu
- Select
- Popover
- Sheet
- Attachment Viewer
- command palette
- custom modal

This is a known class of failure with modal/focus-layer interactions.

If body remains:

pointer-events: none

after a modal closes, identify EXACTLY which component causes it.

Do not simply force:

body.style.pointerEvents = "auto"

globally as a workaround.

Fix the lifecycle/root component causing the stale state.

11. OBJECT URL CLEANUP
==================================================

If Blob/Object URLs are used:

createObjectURL()

must be paired correctly with:

URL.revokeObjectURL()

BUT do not revoke before the image has finished using it.

Audit lifecycle carefully.

Premature revoke can cause broken images.
Missing revoke can create memory leaks and eventual browser slowdown.
