- Clicking a patient row the first time expands it, but not all patient details become visible.
- Clicking the same row again causes the rest of the content to appear.

This strongly suggests the expandable container is using a stale measured height / max-height / scrollHeight before asynchronous detail content finishes rendering.

Fix the expansion implementation so the expanded row always adapts automatically to its real dynamic content height.

Requirements:

- One click must fully open the row.
- If patient details are still loading, show a compact loading state/skeleton.
- When the async details arrive, the same already-open row must automatically grow to display them.
- No second click must ever be required.
- Dynamically opening inline edit forms or quick-action forms must also automatically increase the row height.
- Dynamically closing them must shrink it smoothly.

Do NOT use a fixed or stale max-height.

Prefer a content-driven solution such as:

- CSS grid 0fr → 1fr expansion,
- or another naturally content-sized approach,
- or ResizeObserver only if genuinely necessary.

Avoid manually measuring scrollHeight once and then keeping that stale value.
