## 1. USER PROFILE PHOTO

Add an optional profile photo to each user account.

The photo must be manageable by ADMIN from:

* Settings → المستخدمون → إنشاء مستخدم جديد
* Settings → المستخدمون → تعديل المستخدم

Add a field:

صورة المستخدم

with:

* upload/select image
* preview
* replace image
* remove image

The profile photo is optional.

If no photo exists, preserve a clean fallback avatar using the user's initials.

## 2. IMAGE REQUIREMENTS

Accepted formats:

* JPEG
* PNG
* WebP

Do NOT allow SVG.

Use a safe upload limit such as approximately 1 MB after processing.

Validate both frontend and backend.

Do not trust file extensions alone.

Use the existing reliable image-storage approach already used by the application for the clinic logo where appropriate.

Since this system has a relatively small number of staff users, storing the processed avatar safely in the database is acceptable and preferable to depending on ephemeral local filesystem storage.

Do not expose filesystem paths.

## 3. IMAGE PROCESSING

Keep profile images visually consistent.

When uploading:

* show a square preview
* display the final avatar as a circle
* use object-fit: cover
* preserve reasonable quality
* prevent extremely large uploaded images from creating oversized database records

If lightweight client-side resizing/cropping can be implemented without introducing a heavy dependency, resize the image to a practical avatar size such as approximately 512×512 before upload.

Do not add a large image-editing library just for cropping.

## 4. DATABASE / USER MODEL

Add the minimum required nullable profile-image field to the existing user model.

Create a safe versioned migration.

Do not create a separate complex media-management system.

Existing users must continue working without modification.

The field must be nullable so current users automatically use the fallback avatar.
