MODE: Lite

أريد تحسين تصميم وطريقة اختيار التاريخ/الوقت في النظام لأنها حالياً سيئة بصرياً وتجربة استخدامها غير مريحة، خصوصاً داخل الصفوف الموسعة في التقرير التشغيلي.

## المطلوب

استبدال واجهة اختيار التاريخ/الوقت الحالية بتجربة أبسط وأنظف وأسهل للمستخدم.

## الأماكن المستهدفة

طبّق التحسين على كل حقول التاريخ/الوقت المرتبطة بنفس النمط الحالي، خصوصاً:
- إضافة متابعة
- تعديل متابعة
- أي حقول تاريخ/وقت مشابهة داخل الصفوف الموسعة أو النماذج inline
- وإذا نفس المكوّن مستخدم في أماكن مشابهة بالنظام، وحّده هناك أيضاً بدون كسر أي شيء

## المشكلة الحالية

- نافذة اختيار التاريخ كبيرة ومزعجة بصرياً
- تظهر بشكل غير مريح داخل الجدول
- اختيار التاريخ والوقت معاً ليس سلساً
- التصميم يبدو مزدحمًا ومعقدًا
- تجربة الاستخدام ليست نظيفة ولا سريعة

## الهدف

أريد اختيار تاريخ/وقت:
- بسيط
- واضح
- سريع
- شكله نظيف
- مناسب للواجهة العربية RTL
- يعمل بشكل ممتاز داخل الجدول وداخل النماذج inline
- لا يغطي المحتوى بشكل مزعج
- لا يبدو معقدًا

## التصميم المطلوب

اعتمد أسلوب أبسط كالتالي:

### 1) التاريخ
- حقل واضح للتاريخ
- عند الضغط عليه يظهر Calendar صغير ونظيف فقط
- تقويم بسيط جداً بدون تعقيد
- إغلاقه سهل بعد الاختيار
- لا يكون ضخم أو مزعج
- يتمركز بشكل جيد ولا يغطي عناصر كثيرة حوله
- يدعم RTL بشكل مرتب

### 2) الوقت
- اجعل الوقت منفصلًا عن التاريخ
- لا أريد مكوّن اختيار وقت المعقد الحالي
- استخدم حلاً بسيطًا وواضحًا مثل:
  - dropdown للساعة
  - dropdown للدقائق
  - أو time input واضح جداً إذا كان شكله مناسب
- المهم يكون الاختيار سهل وبسيط وسريع

### 3) العرض النهائي
- بعد الاختيار، تظهر القيمة المختارة بشكل واضح ومقروء
- مثلاً:
  17 أغسطس 2026، 02:35 م
- لو الحقل فارغ يظهر placeholder عربي واضح
  مثل:
  "اختر التاريخ"
  "اختر الوقت"
  أو "اختر التاريخ والوقت"

## قواعد UX

- لا تستخدم popover كبير ومربك
- لا تجعل التقويم يغطي مساحة كبيرة من الجدول
- اجعل التجربة مريحة جداً داخل الصف الموسع
- يجب أن يكون الشكل clean ومتماشٍ مع باقي تصميم النظام
- على الجوال والتابلت يكون الاستخدام أسهل وليس أصعب
- إذا كان الحقل اختياريًا، يجب أن يبقى واضحًا ويمكن تركه فارغًا
- إذا اختار المستخدم تاريخًا فقط ثم وقتًا، يجب أن يتجمعا بشكل صحيح في القيمة النهائية
- دعم keyboard/focus بشكل جيد
- دعم الإغلاق عند الضغط خارج المكوّن

## مهم جداً

لا تغيّر أي منطق backend أو API أو تخزين.
لا تغيّر صيغة التخزين.
لا تغيّر قواعد التحقق.
فقط حسّن واجهة وتجربة اختيار التاريخ/الوقت.

## ما يجب الحفاظ عليه

- نفس السلوك الوظيفي الحالي
- نفس الحقول المطلوبة/الاختيارية
- نفس القيم المرسلة للباكند
- نفس المنطقة الزمنية الحالية
- نفس منطق الحفظ والتعديل

## تحسينات إضافية مطلوبة

- إذا كان هناك خطأ في الحقل، يظهر الخطأ بشكل واضح تحت الحقل نفسه
- لو التاريخ/الوقت مطلوب، وضّح ذلك بصرياً
- اجعل الحقول متناسقة حجماً وارتفاعاً مع بقية حقول النموذج
- اجعل مظهر التاريخ والوقت مناسباً للغة العربية وليس شكلاً إنجليزياً مربكاً
